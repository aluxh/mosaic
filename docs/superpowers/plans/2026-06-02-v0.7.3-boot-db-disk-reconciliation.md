# Boot-time DB / Disk Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On API boot, remove photo DB rows whose original seed/upload file is missing so manual NAS deletes self-heal before the wall serves broken-image slides.

**Spec:** [`../../../../mosaic-specs/v0.7.3-boot-db-disk-reconciliation-spec.md`](../../../../mosaic-specs/v0.7.3-boot-db-disk-reconciliation-spec.md)

## Summary

Implement a small boot reconciliation pass for the active event. The API will check every photo row, resolve its original file location from `source`, delete stale DB rows with the existing message cascade, then continue with seed indexing and variant backfill.

No migration, UI, file deletion, variant cleanup, watcher, or orphan-file pruning.

## Key Changes

- Add a non-admin query helper, `listAllPhotos(db, eventId)`, returning visible and hidden photo rows for reconciliation.
- Add `api/src/lib/reconcilePhotos.ts` with `reconcileMissingPhotos(db, paths, eventId)`.
- Reconciliation behavior:
  - checks seed originals under `data/seeds/<eventId>/`,
  - checks upload originals under `data/uploads/<eventId>/`,
  - keeps rows when the original exists,
  - calls `deletePhotoCascade` when the original is missing,
  - treats unsafe filenames as stale DB rows and removes them,
  - returns `{ checked, removed, removedPhotos }`.
- Wire boot order in `api/src/server.ts`:
  - upsert event and ensure event dirs,
  - run `reconcileMissingPhotos`,
  - run `indexSeedsForEvent`,
  - run `backfillVariants`.
- Log only when stale rows are removed:
  - `[reconcile] removed <n> stale photo rows for <eventId>`
  - do not log absolute host paths.
- Update the approved spec status and roadmap status after implementation ships.

## Test Plan

- Query tests:
  - `listAllPhotos` includes visible and hidden photos for the requested event.
  - `deletePhotoCascade` existing tests remain the cascade contract.
- New reconciliation tests:
  - keeps seed and upload rows whose original files exist,
  - removes missing seed rows,
  - removes missing upload rows,
  - deletes linked messages for removed photos,
  - preserves standalone messages,
  - checks hidden photo rows and removes hidden stale rows,
  - treats unsafe filenames as stale without reading arbitrary paths,
  - is idempotent on a second run.
- Boot-order test:
  - a stale seed row is removed before seed indexing, allowing a present/re-added seed file with the same filename to be indexed during that boot flow.
- Verification commands:
  - `npm --prefix api run test -- --run test/queries.test.ts`
  - `npm --prefix api run test -- --run test/reconcilePhotos.test.ts`
  - `npm --prefix api run test -- --run test/seedIndex.test.ts`
  - `npm --prefix api run test -- --run`
  - `npm --prefix api run typecheck`

## Assumptions And Defaults

- Zero-removal boots stay quiet.
- Stale variants are left on disk for a later storage-pruning phase.
- Reconciliation is scoped to the active single event booted by `EVENT_MODE`.
- Reconciliation deletes DB rows and linked messages only; it never deletes original files or variants.
