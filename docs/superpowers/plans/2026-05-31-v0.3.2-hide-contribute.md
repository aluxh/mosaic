# v0.3.2 — Hide Contribute Affordance Without a Token — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hide the "Add to the wall" button and disable the `c` keyboard shortcut when no capability token is present in the URL hash, so only QR-poster guests are invited to upload.

**Architecture:** Pure frontend change. `App.tsx` already reads the token once at mount via `readToken()`. Derive a `canContribute` boolean from it, gate the button's render on it, and pass the open handler to the keyboard hook only when contribution is allowed. The keyboard hook makes `onOpenContribute` optional so an absent handler is a no-op. The API gate is the real security boundary and is unchanged.

**Tech Stack:** React 18 + TypeScript, Vitest + @testing-library/react (jsdom).

**Spec:** [`../../../../mosaic-specs/v0.3.2-hide-contribute-spec.md`](../../../../mosaic-specs/v0.3.2-hide-contribute-spec.md)

- [ ] **Step 1: Write the failing tests**

Insert this `describe` block immediately after the closing `});` of the `App keyboard shortcuts` block (currently line 82) and before `describe('App renders event theme'`:

```ts
describe('App contribute gate', () => {
  it('shows the contribute button when a token is present', async () => {
    window.location.hash = '#t=test';
    await renderApp();
    expect(screen.getByText(/add to the wall/i)).toBeInTheDocument();
  });

  it('hides the contribute button when no token is present', async () => {
    window.location.hash = '';
    await renderApp();
    expect(screen.queryByText(/add to the wall/i)).not.toBeInTheDocument();
  });

  it('does not open the contribute sheet with "c" when no token is present', async () => {
    window.location.hash = '';
    await renderApp();
    act(() => {
      fireEvent.keyDown(window, { key: 'c' });

    expect(screen.queryByText(/leave a remembrance/i)).not.toBeInTheDocument();
  });
});
```

The `token` value is read in `App` via `useMemo(..., [])` at mount, so the hash must be set before `render`, which `renderApp()` does — setting it at the top of the test body is correct.

## Notes for the implementer

- **Why presence-only:** the token is signed with a server-side secret the client can't verify. We gate on presence, not validity, by design (see spec Non-goals).
- **Why the button stays unmounted vs. hidden via CSS:** conditional render (`{canContribute && ...}`) removes it from the DOM, which is what the test asserts (`queryByText(...).not.toBeInTheDocument()`).
- **`Escape` stays unconditional:** harmless when the sheet can never open; no change needed.
