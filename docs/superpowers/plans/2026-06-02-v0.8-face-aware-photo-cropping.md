# v0.8 Face-Aware Photo Cropping Implementation Plan

**Goal:** Store face-aware focal-point metadata for photos and use it as CSS
`object-position` in slideshow cover crops.

**Architecture:** Use `face-api.js` Tiny Face Detector with the pure JS CPU
backend. Detection runs at upload, seed indexing, and boot backfill only. A
shared queue with concurrency `2` bounds CPU pressure during burst uploads.

**Spec:** [`../../../../mosaic-specs/v0.8-face-aware-photo-cropping-spec.md`](../../../../mosaic-specs/v0.8-face-aware-photo-cropping-spec.md)

## Key Changes

- Add API dependencies: `face-api.js` and `canvas`; vendor Tiny Face Detector
  model files under API source so production never downloads models at runtime.
- Add Docker support for `canvas` by installing Cairo/Pango/image
  build/runtime libraries in `Dockerfile.api`.
- Add `photos.focal_x` and `photos.focal_y` via migration
  `005_photo_focal_point.sql`, defaulting both to `0.5`.
- Extend photo row/types/API payloads and web photo models with focal fields.
- Add `api/src/lib/focalPoint.ts` with lazy model load, bounded detection
  queue, downscaled inference input, multi-face union center, clamping, and
  center fallback.
- Add `backfillFocalPoints(db, paths, eventId)` and call it after variant
  backfill on boot.
- Detect focal points during upload and seed indexing before inserting photo
  rows.
- Add `objectPositionForPhoto(photo)` in web code and apply it to hero,
  hero-with-message, duo, triptych, and polaroid slides.

## Public Interfaces

- API photo objects gain `focal_x: number` and `focal_y: number`.
- Web photo objects gain `focalX: number` and `focalY: number`.
- No new routes; no upload request-shape changes; no variant URL changes.

## Test Plan

- API tests: migration defaults/idempotency, query focal persistence, focal
  helper fallback/union/clamping/queue concurrency, seed indexing, boot
  backfill, upload/event/admin route payloads.
- Web tests: API/admin mappers default and map focal fields; slide image
  components apply expected `object-position`.
- Verification commands:
  - `npm --prefix api run test -- --run`
  - `npm --prefix web run test -- --run`
  - `npm --prefix api run typecheck`
  - `npm --prefix web run typecheck`
  - build API Docker image to verify `canvas` installs in production.

## Assumptions

- Detection queue concurrency is fixed at `2`; no env var in v0.8.
- Detection failures never reject uploads or block boot; they fallback to
  center.
- Existing rows at `0.5, 0.5` may be recalculated once on first boot after the
  migration.
