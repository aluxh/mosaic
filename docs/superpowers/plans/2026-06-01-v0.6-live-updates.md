# v0.6 Live Updates — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** `../mosaic-specs/v0.6-live-updates-spec.md`

## Summary

Implement one-way live slideshow refresh with Server-Sent Events. The API will
expose a public `GET /api/events/:id/stream` endpoint, publish update
notifications after successful photo/message writes, and the web app will
prefer `EventSource` over the current 10 second polling loop while keeping
polling as fallback.

No database migration, auth change, WebSocket support, or full payload
streaming.

## Key Changes

- Add an in-process API live-update bus with scoped subscriptions by `eventId`.
- Add SSE route behavior:
  - unknown event returns `404`,
  - known event sends `text/event-stream`,
  - initial `event: ready` frame,
  - update frames use `event: mosaic-update` with JSON `{ type, eventId, createdAt }`,
  - heartbeat comment every `25_000ms`,
  - cleanup subscriber and heartbeat on disconnect.
- Publish updates only after successful writes:
  - text-only message POST publishes `message_created`,
  - photo upload publishes `photo_created`,
  - photo upload with linked message publishes `photo_created` and `message_created`.
- Replace `usePolling(refresh, POLL_MS)` with a `useLiveUpdates(eventId, refresh, 10_000)` hook:
  - immediate refresh remains in `App`,
  - `EventSource` refreshes on `mosaic-update`,
  - fallback polling starts when `EventSource` is missing or errors,
  - fallback preserves `document.hidden` skip behavior.
- Update nginx only if required for SSE buffering:
  - preferred minimal change: add `proxy_buffering off;` under existing `/api/`,
  - add a config regression test only if nginx changes.

## Public Interfaces

- New read endpoint: `GET /api/events/:id/stream`
- New SSE event names:
  - `ready`
  - `mosaic-update`
- New update payload type:
  - `type LiveUpdate = { type: 'photo_created' | 'message_created'; eventId: string; createdAt: number }`
- Existing endpoints remain authoritative:
  - `/api/events/:id/photos`
  - `/api/events/:id/messages`

## Test Plan

- API unit tests:
  - subscriber receives only matching event id updates,
  - unsubscribe stops delivery,
  - one failing subscriber does not block others.
- API integration tests:
  - stream returns `404` for unknown event,
  - stream returns SSE headers and initial ready frame,
  - text-only message emits `message_created`,
  - photo upload emits `photo_created`,
  - photo upload with linked message emits both update types,
  - stream route stays public while write routes still require tokens.
- Web tests:
  - `EventSource` opens `/api/events/remembrance/stream`,
  - `mosaic-update` calls `refresh`,
  - cleanup closes `EventSource`,
  - missing `EventSource` falls back to polling,
  - stream error closes source and falls back,
  - fallback skips refresh while `document.hidden`,
  - `App` initial load still fetches events/photos/messages,
  - live update refreshes counters.
- Verification commands:
  - `npm --prefix api run test -- --run`
  - `npm --prefix api run typecheck`
  - `npm --prefix web run test -- --run`
  - `npm --prefix web run typecheck`

## Assumptions And Defaults

- Heartbeat interval is fixed at `25_000ms`.
- SSE payloads remain minimal notifications; clients refetch JSON lists for truth.
- Stream reads remain public, matching existing read-route behavior.
- The shipped single-process API makes in-memory fanout acceptable.
- Optimistic local append in `App` stays; SSE refresh reconciles by replacing arrays.
