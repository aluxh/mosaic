# v0.1.4 — Self-hosted Fonts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Google Fonts CDN `<link>` in `web/index.html` with bundled WOFF2 files via `@fontsource` so the deployed app renders Inter / Instrument Serif / JetBrains Mono in environments where the CDN is blocked (current Synology NAS deploy).

**Architecture:** Three `@fontsource` npm packages (one per family) installed as runtime deps of the `web` workspace. Per-weight CSS files imported from `web/src/main.tsx` — Vite bundles the referenced WOFF2 with content-hashed asset URLs. The Google Fonts `<link>` and the two `<link rel="preconnect">` lines in `web/index.html` are deleted. Existing `font-family` declarations in `web/src/index.css` stay byte-for-byte; `@fontsource` registers the same family names.

**Tech Stack:** Vite 6, React 18, TypeScript, Vitest 2 (jsdom), `@fontsource/inter`, `@fontsource/instrument-serif`, `@fontsource/jetbrains-mono`.

**Spec:** [`../../../mosaic-specs/v0.1.4-self-hosted-fonts-spec.md`](../../../mosaic-specs/v0.1.4-self-hosted-fonts-spec.md)

## Task 1: Regression test for absent Google Fonts CDN reference

**Goal:** A failing test that asserts `web/index.html` contains no reference to `fonts.googleapis.com` or `fonts.gstatic.com`. Test will FAIL today (links present) and PASS after Task 2 strips them.

**Files:**
- Create: `web/src/test/fonts.test.tsx`

- [ ] **Step 1: Write the failing test**

Create `web/src/test/fonts.test.tsx`:

```tsx
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import path from 'node:path';
import { describe, it, expect } from 'vitest';

const here = path.dirname(fileURLToPath(import.meta.url));
const indexHtmlPath = path.resolve(here, '../../index.html');

describe('fonts', () => {
  it('does not load fonts from the Google Fonts CDN', () => {
    const html = readFileSync(indexHtmlPath, 'utf-8');
    expect(html).not.toMatch(/fonts\.googleapis\.com/);
    expect(html).not.toMatch(/fonts\.gstatic\.com/);
  });
});
```

- [ ] **Step 2: Run the test, verify it fails**

Run from repo root:

```
npm run test:web -- --run src/test/fonts.test.tsx
```

Expected: **FAIL** — two assertion errors:
- `Expected "<...>" not to match /fonts\.googleapis\.com/`
- `Expected "<...>" not to match /fonts\.gstatic\.com/`

If the test passes, STOP — the Google Fonts links are already gone and something is off; verify `web/index.html` still has the CDN `<link>` lines before proceeding.

- [ ] **Step 3: Do not commit yet** — the test is failing intentionally. The green commit happens at the end of Task 2.

- [ ] **Step 3: Add the nine font-CSS imports to `web/src/main.tsx`**

Current file (`web/src/main.tsx`):

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import './index.css';
```

Replace with:

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

// Self-hosted fonts (v0.1.4) — replaces the Google Fonts CDN link.
// Latin subset, only the weights/styles used by web/src/index.css.
import '@fontsource/inter/300.css';
import '@fontsource/inter/400.css';
import '@fontsource/inter/500.css';
import '@fontsource/inter/600.css';
import '@fontsource/inter/700.css';
import '@fontsource/instrument-serif/400.css';
import '@fontsource/instrument-serif/400-italic.css';
import '@fontsource/jetbrains-mono/400.css';
import '@fontsource/jetbrains-mono/500.css';

import './index.css';
import { App } from './App';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

Note: the font imports come **before** `./index.css` so that the global font-family rules cascade over already-registered `@font-face` declarations. (Order between the two is not behaviorally significant for CSSOM but keeping fonts first matches the convention `@fontsource` documents.)

## Task 3: Verify bundle-size acceptance criterion

**Goal:** Confirm the bundled font assets total ≤ 250 KB (spec acceptance criterion). Pure verification — no code changes, no commit unless something is off.

**Files:** none (read-only inspection of `web/dist/`).

- [ ] **Step 1: Inspect bundled font files**

After `npm --prefix web run build` from Task 2, run:

```
find web/dist/assets -name '*.woff2' -printf '%s\t%p\n' | sort -n
```

Expected: nine `.woff2` files (one per imported weight/style), Latin subset, each in the tens of KB.

- [ ] **Step 2: Sum the total**

Run:

```
find web/dist/assets -name '*.woff2' -printf '%s\n' | awk '{s+=$1} END {printf "%d bytes (%.1f KB)\n", s, s/1024}'
```

Expected: total ≤ **256000 bytes (250 KB)**. Typical observed range for nine Latin-subset weights is ~120–200 KB.

If the total exceeds 250 KB, STOP and investigate — possible causes:
- An `@fontsource` package shipped a non-Latin subset by default (check the imported path; the per-weight default `400.css` is Latin)
- An extra import sneaked in

Fix the import list in `web/src/main.tsx`, rebuild, re-measure. No commit needed if all is well; the assets aren't checked into git.
