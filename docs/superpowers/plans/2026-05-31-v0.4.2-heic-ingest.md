# v0.4.2 — HEIC Ingest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept HEVC-compressed HEIC uploads (and seeds) from iPhones, transcoding them to JPEG through the existing v0.4 variant pipeline, while continuing to reject AVIF.

**Architecture:** `ingestImage` content-sniffs Sharp's decoded metadata and accepts `format==='heif'` only when `compression==='hevc'` (HEIC), normalizing to JPEG; AVIF (`av1`) stays rejected. The upload route already renames to `${id}.jpg`, so it needs no change. Seed indexing gains rename-on-transcode so a `.heic` seed becomes a `.jpg` photo. The production Docker image installs a global libvips with `libheif`/`libde265` and forces Sharp to build against it, since Sharp's prebuilt libvips omits HEVC.

**Tech Stack:** Node 20, TypeScript (tsx), Sharp 0.33.5, Vitest, Fastify, Debian `node:20-bookworm-slim`.

**Spec:** [`../../../../mosaic-specs/v0.4.2-heic-ingest-spec.md`](../../../../mosaic-specs/v0.4.2-heic-ingest-spec.md)

## Prerequisite (human): commit a HEIC fixture

Before running the HEIC-accept tests, place one **small, clean, real iPhone HEIC** (HEVC-compressed) at:

```
api/test/fixtures/iphone.heic
```

The accept-path tests **skip at runtime** (not fail) when the fixture is missing OR when the local Sharp build cannot decode HEVC (no `libde265`). They use a runtime guard — `async (ctx) => { if (!heicReady) { ctx.skip(); return; } ... }` — **not** `it.skipIf(!heicReady)`: `skipIf` evaluates its condition at collection time, before `beforeAll` populates `heicReady`, so it would skip unconditionally and never run even where HEVC decode is available. The authoritative codec check is the Docker verification in Task 4. The reject-AVIF and error-string tests do not need the fixture and always run.

```ts
import sharp from 'sharp';

export const MAX_FILE_BYTES = 10 * 1024 * 1024;

type IngestResult =
  | { ok: true; buf: Buffer; format: 'jpeg' | 'png' | 'webp'; ext: '.jpg' | '.png' | '.webp' }
  | { ok: false; code: 400 | 413 | 415; error: string };

export async function ingestImage(input: Buffer, maxBytes: number): Promise<IngestResult> {
  if (input.byteLength > maxBytes) {
    return { ok: false, code: 413, error: `file too large (max ${Math.round(maxBytes / (1024 * 1024))}MB)` };
  }

  let meta: Awaited<ReturnType<sharp.Sharp['metadata']>>;
  try {
    meta = await sharp(input).metadata();
  } catch {
    return { ok: false, code: 400, error: 'invalid or corrupt image' };
  }

  // Sharp reports both HEIC and AVIF as format 'heif'; they differ only by
  // compression. Accept HEVC-compressed HEIF (real iPhone HEIC); AVIF ('av1')
  // stays rejected.
  const isHeic = meta.format === 'heif' && meta.compression === 'hevc';
  const accepted =
    meta.format === 'jpeg' || meta.format === 'png' || meta.format === 'webp' || isHeic;
  if (!accepted) {
    return { ok: false, code: 415, error: 'unsupported image type — JPEG, PNG, WebP, or HEIC only' };
  }

  // HEIC normalizes to JPEG, matching the existing JPEG path (rotate + strip EXIF).
  const outFormat: 'jpeg' | 'png' | 'webp' =
    meta.format === 'png' ? 'png' : meta.format === 'webp' ? 'webp' : 'jpeg';

  let buf: Buffer;
  if (outFormat === 'jpeg') {
    buf = await sharp(input).rotate().jpeg({ quality: 95, mozjpeg: true }).toBuffer();
  } else if (outFormat === 'png') {
    buf = await sharp(input).rotate().png({ compressionLevel: 9 }).toBuffer();
  } else {
    buf = await sharp(input).rotate().webp({ quality: 95 }).toBuffer();
  }

  const ext = outFormat === 'jpeg' ? '.jpg' : outFormat === 'png' ? '.png' : '.webp';
  return { ok: true, buf, format: outFormat, ext };
}
```

- [ ] **Step 1: Rewrite `Dockerfile.api` to install the codec stack and force global libvips**

```dockerfile
FROM node:20-trixie-slim
WORKDIR /app

# HEIC (HEVC) decode needs a global libvips with libheif + a libde265 decode
# plugin; Sharp's bundled prebuilt libvips omits HEVC. Debian trixie ships libvips
# >= 8.15.3 (Sharp 0.33.5's floor) and a libheif libde265 decode plugin, so we
# install the distro codec stack and force Sharp to compile its native addon
# against the global libvips. node-addon-api + node-gyp are installed globally
# (and exposed via NODE_PATH) because Sharp does not declare them yet needs them
# to build from source. Decode only — no x265 encoder, since HEIC is transcoded
# to JPEG on ingest.
RUN apt-get update && apt-get install -y --no-install-recommends \
      pkg-config python3 make g++ \
      libvips-dev libheif-plugin-libde265 \
    && rm -rf /var/lib/apt/lists/* \
    && npm install -g --no-audit --no-fund node-addon-api@^7 node-gyp

ENV SHARP_FORCE_GLOBAL_LIBVIPS=1
ENV NODE_PATH=/usr/local/lib/node_modules

COPY tsconfig.base.json ./
COPY api/package.json api/package-lock.json* ./api/
RUN cd api && npm install --no-audit --no-fund --omit=dev
```

`node-addon-api` MUST be pinned to v7: v8 requires C++17 (`std::string_view`), which Sharp 0.33.5's build does not enable, so v8 fails to compile the addon.
