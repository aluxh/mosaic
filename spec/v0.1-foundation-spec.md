# v0.1 — Foundation Spec

**Status:** In progress
**Roadmap entry:** [`roadmap.md#v01-foundation`](roadmap.md)

## Context

Mosaic is a self-hosted "Shared Memory Wall" web app — a fullscreen
auto-advancing slideshow of host-seeded photos plus guest contributions,
designed to run on a TV at memorials and weddings. Guests scan a QR code
on their phones, see the live slideshow, and tap "Add to wall" to upload
a photo or leave a written message.

The source design is a polished HTML/JSX prototype (in
`/tmp/design-extract/mosaic/`) — visual spec only, not production code.
v0.1 rebuilds it in production-appropriate tech, adds persistence, and
makes it deployable on Synology via Docker.

## Goals

1. The slideshow renders correctly on a 1080p TV display, matching the
   prototype's visual design pixel-for-pixel in both modes.
2. A guest can upload a photo via the contribute sheet on their phone; the
   photo persists on the Synology volume and appears in the slideshow
   within 15 seconds (one polling interval).
3. A guest can submit a written message; same persistence + appearance.
4. Seed photos placed in `/data/seeds/{eventId}/` are picked up
   automatically on backend startup.
5. The entire stack runs via `docker compose up` on Synology Container
   Manager with one bind-mount to `/volume1/docker/mosaic/data`.
6. Unit tests cover all pure logic; component tests cover key interactions.

## Non-goals (v0.1)

- Auth, rate limiting, CSP — deferred to v0.2
- Thumbnail generation — deferred to v0.2; serve originals
- EXIF stripping — deferred to v0.2 (security/privacy fix)
- Multi-event support — single hardcoded event for v0.1
- Host moderation UI — moderate by editing files on disk
- Real-time push — polling at 10s intervals
- Mobile-responsive testing across many devices — target iPhone Safari + Chrome on TV

## User stories

1. **As a host**, I drop my photos into `/volume1/docker/mosaic/data/seeds/remembrance/`
   and they appear in the slideshow on next backend restart.
2. **As a guest**, I open `http://mosaic.local/` on my phone, tap "Add to the
   wall", pick a photo from my camera roll, optionally add my name and a
   short message, tap submit, see a "Just added" confirmation, and within
   15 seconds the photo appears in the rotation on the TV display.
3. **As a guest**, I can submit a written message without a photo; it
   appears as a `message` slide in the rotation.
4. **As the host**, I press `m` on a keyboard plugged into the display to
   switch modes between Celebration and Remembrance.
5. **As the host**, I press space to pause the slideshow.

## Data model

```sql
CREATE TABLE events (
  id           TEXT PRIMARY KEY,           -- 'celebration' | 'remembrance' (hardcoded in v0.1)
  mode         TEXT NOT NULL,              -- same as id in v0.1
  eyebrow      TEXT NOT NULL,
  title        TEXT NOT NULL,
  dateline     TEXT NOT NULL,
  place        TEXT NOT NULL,
  invitation   TEXT NOT NULL,
  brand_sub    TEXT NOT NULL,
  short_code   TEXT NOT NULL              -- displayed on title card, e.g. '4F8K'
);

CREATE TABLE photos (
  id           TEXT PRIMARY KEY,           -- uuid for uploads, 'seed-<filename>' for seeds
  event_id     TEXT NOT NULL REFERENCES events(id),
  source       TEXT NOT NULL,              -- 'seed' | 'upload'
  filename     TEXT NOT NULL,              -- relative to /data/{source}s/{eventId}/
  credit       TEXT NOT NULL,              -- guest name or 'Host'
  created_at   INTEGER NOT NULL            -- unix ms
);
CREATE INDEX idx_photos_event ON photos(event_id, created_at);

CREATE TABLE messages (
  id           TEXT PRIMARY KEY,
  event_id     TEXT NOT NULL REFERENCES events(id),
  name         TEXT NOT NULL,
  text         TEXT NOT NULL,              -- max 240 chars enforced in API
  created_at   INTEGER NOT NULL
);
CREATE INDEX idx_messages_event ON messages(event_id, created_at);
```

## API surface

| Method | Path | Body | Returns |
|---|---|---|---|
| GET  | `/api/events`                            | — | `Event[]` |
| GET  | `/api/events/:id/photos`                 | — | `Photo[]` (with URLs resolved) |
| GET  | `/api/events/:id/messages`               | — | `Message[]` |
| POST | `/api/events/:id/photos`                 | multipart: `file`, `credit?` | `Photo` |
| POST | `/api/events/:id/messages`               | `{name?, text}` | `Message` |
| GET  | `/data/seeds/:eventId/:filename`         | — | image bytes (served by nginx) |
| GET  | `/data/uploads/:eventId/:filename`       | — | image bytes (served by nginx) |

Frontend polls `GET /api/events/:id/photos` and `/messages` every 10 seconds
and merges new entries into local state.

## Tests (TDD targets)

**Frontend — pure logic:**
- `buildSequence.test.ts`
  - empty input → empty sequence
  - 1 photo + 0 messages → title card + hero
  - hero/duo/triptych/polaroid/hero-msg/message patterns appear per mode
  - sequence cycles correctly (no off-by-one)
  - title-card recurs once per pattern cycle
  - celebration vs remembrance use different patterns
- `hash.test.ts`
  - deterministic for same input
  - returns value in [0, 1)
  - different salts produce different values

**Frontend — components:**
- `ContributeSheet.test.tsx`
  - submit disabled when no file and no message
  - file picker stores preview URL
  - submit calls onSubmit with trimmed values
  - close clears state after 500ms
  - 240 char counter updates
- `App.test.tsx`
  - `m` toggles mode
  - `space` toggles paused
  - `c` opens contribute sheet
  - `Escape` closes contribute sheet
  - Shortcuts ignored when focus is in input/textarea

**Backend:**
- `seedIndex.test.ts`
  - empty seeds folder → no rows
  - jpg/jpeg/png files indexed; other extensions skipped
  - re-running is idempotent (no duplicate rows)
  - removed files are NOT auto-deleted from DB in v0.1 (documented behavior)
- `photos.test.ts`
  - GET returns merged seed + upload photos sorted by created_at desc
  - POST writes to disk + DB, returns created row
  - POST rejects files > 10MB
- `messages.test.ts`
  - POST validates `text` non-empty and ≤ 240 chars
  - GET returns messages for event id
- `uploads.test.ts`
  - file written to correct subdirectory
  - filename collision uses uuid prefix

## Acceptance criteria

The feature is done when:

1. `npm install && npm test` passes at the repo root (runs frontend + backend test suites).
2. `npm run dev` starts both servers; opening `http://localhost:5173/` shows the slideshow with seed data.
3. Dropping a jpg into `./data/seeds/remembrance/` and restarting the API makes the photo appear in the rotation.
4. Submitting via the contribute sheet creates a row in SQLite and the file appears in `./data/uploads/`. The new content shows up in the slideshow within 10 seconds.
5. Keyboard shortcuts (m/space/c/Esc) work as specified.
6. `docker compose up --build` brings up both containers; the app is reachable on the host's port 80 and survives container restarts (data persists).
7. The slideshow's visual output matches the prototype in both modes (Celebration warm/fast, Remembrance cool/slow).

## Verification (manual)

1. `npm install` at repo root.
2. `npm run dev` starts Vite (5173) + Fastify (3000) concurrently.
3. Drop 3 jpgs into `./data/seeds/remembrance/`.
4. Restart API → `curl http://localhost:3000/api/events/remembrance/photos` returns 3 rows.
5. Open `http://localhost:5173/` → slideshow plays in remembrance mode.
6. Press `m` → switches to celebration mode.
7. Press `c` → contribute sheet opens.
8. Upload a photo + add message → "Just added" toast → within 10s the new content appears.
9. `docker compose build && docker compose up` → app reachable at `http://localhost/`.
10. All vitest suites pass (`npm test`).
